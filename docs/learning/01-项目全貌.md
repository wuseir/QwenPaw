# 项目全貌：先认识各部分的职责

状态：这是源码和项目文档基础上的入门讲解，不代表学习者已经阅读或验证。

源码研究基线：`45c754ee694c3e27ced3d27f8971449be067f534`。

## 项目解决什么问题

QwenPaw 是在自己的电脑或服务环境里运行的个人 AI 助手。它可以通过网页或其他消息渠道与用户交互，再通过工具、Skills 和模型处理任务。

普通聊天只返回文字；这类助理还需要真正读取资料、执行程序、管理任务和保存会话。先学习网页中的一条处理链，不把所有渠道一起展开。

使用者可以是希望处理个人资料、文件和重复任务的人。首轮用不含私密资料的小样本实验。

来源：[中文 README](https://github.com/wuseir/QwenPaw/blob/45c754ee694c3e27ced3d27f8971449be067f534/README_zh.md)。

## 各部分分别做什么

| 部分 | 通俗解释 | 项目入口 |
| --- | --- | --- |
| React 控制台 | 用户输入、按钮、消息显示和交互状态 | `console/` |
| FastAPI 后端 | 接收 HTTP 请求，校验数据，组织运行与返回结果 | `src/qwenpaw/app/` |
| Agent | 结合消息与工具，组织模型处理任务的过程 | `src/qwenpaw/agents/` |
| 模型 | 接收上下文，生成回答或提出工具调用 | 模型配置及 AgentScope 集成，后续跟踪 |
| 工具 | 真正执行文件读取等具体操作的程序 | 工具与插件相关代码，按所选样本定位 |
| 本地存储 | 跨请求、跨重启保存不同类型的数据 | 会话 JSON、Scroll SQLite 历史和其他文件机制 |

不要把上表当成“一张聊天记录表”的设计：不同存储有不同职责，后续要跟随实际读写路径验证。

## 先区分三个概念

**模型与工具**：模型提出“读取某文件”的请求，程序工具真正打开文件；模型本身不等于文件读取函数。

**当前上下文与持久历史**：上下文是模型本次能读取的内容。历史可以保存在外部，未必每次都完整发送给模型。

**会话状态与长期知识**：保存会话便于继续运行；长期知识记忆是另一套按需组织与检索信息的机制。不能只因为都叫 Memory 就视为同一个东西。

## 为什么先学这条链

前端开发经验能够帮助理解页面与 HTTP，再从后端入口追踪一个任务。这样可以按需补 Python、异步和存储知识，避免先背大量理论。

目前只确认了部分源码和文档结构。启动、真实模型、工具调用、停止与恢复均待家庭环境实测。
