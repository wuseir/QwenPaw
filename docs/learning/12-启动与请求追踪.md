## Windows 源码启动步骤

在仓库根目录打开 PowerShell。每段成功后再执行下一段，失败时先看错误，不继续连着执行。

依据：[源码基线安装说明](https://github.com/wuseir/QwenPaw/blob/45c754ee694c3e27ced3d27f8971449be067f534/README_zh.md#从源码安装)。家里源码若有变化，先核对当前说明。

### 1. 检查环境

```powershell
python --version
node --version
npm --version
```

Python 声明为 >=3.11、<3.14；Node 对照 .nvmrc 及实际依赖要求。办公电脑版本不代替家庭电脑检查，不盲目改全局环境。

### 2. 首次准备前端

```powershell
cd console
npm ci
npm run build
cd ..
New-Item -ItemType Directory -Force -Path .\src\qwenpaw\console | Out-Null
Copy-Item -Path .\console\dist\* -Destination .\src\qwenpaw\console -Recurse -Force
```

构建把 React 源码转换为网页文件，复制后由 Python 服务一起提供访问。首次运行可以只启动一个服务，先不引入前后端开发服务器的额外路径。

### 3. 首次准备 Python 环境

若本机尚无项目 .venv：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e .
```

.venv 隔离项目依赖；-e 使用当前源码进行可编辑安装。已有环境时先检查，不覆盖其他用途的环境。

### 4. 首次初始化与启动

仅当本机尚未初始化 QwenPaw 时执行：

```powershell
.\.venv\Scripts\qwenpaw.exe init
```

按交互提示配置。已有本地配置时不重复初始化，不覆盖原有配置。

启动服务：

```powershell
.\.venv\Scripts\qwenpaw.exe app
```

打开 [http://127.0.0.1:8088/](http://127.0.0.1:8088/)。需要时在“设置 → 模型”中本地配置模型服务。密钥不贴进聊天，不提交 Git。

以后的常规启动只需在仓库根目录执行 app 命令。保持服务终端打开；正常停止使用 Ctrl+C。

以上是启动指导，不代表家庭环境已验收。本次只有用户报告的那台电脑取得问候回复。

## 下一课：捕捉一次真实聊天请求

预计 20～30 分钟。目的：把已经读过的路由与浏览器实际请求对应起来。

1. 打开控制台页面，按 F12，进入 Network（网络）。
2. 清空旧记录，发送一次简单消息，例如“你好”。
3. 找到对应聊天请求；不要只凭名字猜，用请求方法、路径和发送时间确认。
4. 记录以下三个字段。

| 字段 | 你的观察 |
| --- | --- |
| Request URL 的路径部分 | 待填写；敏感查询参数先移除 |
| Request Method | 待填写 |
| Response Headers 的 Content-Type | 待填写 |

不复制 Authorization、Cookie、API Key、完整聊天数据或带凭据的 URL。当前练习不需要上传 HAR 文件。

### 对应源码

- `src/qwenpaw/app/_app.py`：应用挂载 API 路由。
- `src/qwenpaw/app/routers/__init__.py`：控制台路由注册。
- `src/qwenpaw/app/routers/console.py`：`post_console_chat` 与流式响应。

仓库同时存在普通路由和按 Agent 作用域挂载的路由，以实际请求为准，不先写死路径答案。前端实际使用的请求函数是下一步要定位的内容。

### 理解检查
