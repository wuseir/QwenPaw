# 第一轮学习路线图

## 目标与范围

首轮按 14 个学习日规划，暂按每天 2～3 小时估计，总计约 28～42 小时。时间预算尚未由学习者确认；14 天是安排单位，不是精通承诺。遇到关键知识点未理解，先补课再推进。

完成目标：

- 跑通一个真实项目。
- 解释页面到后端、模型和工具的完整核心调用链。
- 对 3～5 个核心模块形成有源码和实验依据的理解。
- 完成至少一个有实际价值、可验证的小扩展。
- 讲清楚一项技术取舍，并区分开源功能与自己的贡献。

首轮主线：

> 网页控制台 → FastAPI 接口 → 单个 Agent → 一个工具 → 流式结果 → 会话与历史保存。

首轮暂缓：多消息渠道、多 Agent、桌面打包、复杂沙盒部署和完整长期记忆系统。PostgreSQL、Redis、复杂 RAG 不强行纳入这条最小链路。

## 为什么选 QwenPaw

它有真实网页、Python 后端、工具执行和持久化，便于从前端经验出发追踪完整请求。官方提供 Windows 运行资料，基本路径不要求先管理多个外部数据库服务。

边界也要保留：项目并非小型教学样例，部分文件较大；Agent 能力部分依赖 AgentScope。读懂本项目如何集成框架，不等于实现了整个框架。数据库和企业多用户架构可以后续再学习。

## 14 天安排

| 学习日 | 单元 | 交付或检查点 |
| --- | --- | --- |
| 1 | 源码获取、项目地图、请求入口 | 确认版本，找到路由，回答第一单元四个问题 |
| 2 | 独立开发环境与最小启动 | 检查家庭环境，配置本地模型连接，完成一次真实请求；不记录密钥 |
| 3 | 请求链与随用随学的 Python | 对照浏览器请求，定位后端函数；解释参数与返回值 |
| 4 | SSE 与页面状态 | 标出开始、内容增量、错误和结束，记录真实事件样本 |
| 5 | 一次真实工具调用 | 说明工具描述、参数、执行、结果和后续模型处理 |
| 6 | 工具失败与模型失败 | 分别制造可控失败，解释错误如何到达页面 |
| 7 | 第一轮检查与补课 | 不看笔记讲调用链，纠正不清楚的环节 |
| 8 | 会话保存与 SQLite 历史 | 重启检查保存结果，区分会话状态和历史存储 |
| 9 | 上下文与记忆边界 | 以小实验观察旧消息保存、移出当前上下文和重新读取 |
| 10 | 断连、主动停止和超时 | 比较三种操作，记录服务端任务与页面状态 |
| 11 | 学习者先设计小扩展 | 写需求、输入输出、失败场景、范围和验收条件 |
| 12 | 学习者实现核心路径 | AI 先提示、再局部辅助；形成最小可用功能 |
| 13 | 测试与真实页面验收 | 覆盖正常、错误、重复操作和重启；按需要测耗时 |
| 14 | 演示、复盘与模拟面试 | 展示结果，解释设计取舍、验证依据和改进空间 |

若启动受环境或网络影响超过一个单元，重新分配时间；不要靠省略验证或假定理解来维持日程。

## 每个技术单元的教学流程

1. 通俗解释：用前端概念或生活例子建立直觉。
2. 为什么需要：解决什么问题，不用会怎样，有什么局限。
3. 回到源码：版本、路径、函数、关键片段及模块关系。
4. 深入机制：解释执行过程、状态和资源，而不只翻译代码。
5. 替代方案：比较适用场景；没有设计文档时，把作者动机标为推断。
6. 小实验：先让学习者尝试，再分层给提示。
7. 理解检查：3～5 个问题，覆盖概念、实现、选择、异常或优化。

单元结束记录：理解了什么、仍有什么盲区、实验依据、下一目标。

## 拟议扩展：带实验依据的学习任务工具

需求：学习者通过 Agent 创建、查询、完成学习任务，并为任务附上源码路径或实验记录。

可能的工程内容：参数校验、一个小型持久化模型、状态更新、工具结果和自动化测试。

目前只是候选，尚未设计、实现或验收。开始前先核对现有功能和插件接口，避免重复已有能力；由学习者先写需求与方案。不要为它提前替换项目原有会话或记忆存储。

## 阶段验收

- 启动：真实页面能发请求，并得到预期结果。
- 调用链：能沿一次请求指出关键文件和数据变化。
- 核心模块：能解释正常与失败过程，完成一个小实验。
- 扩展：有清晰需求、本人决策、差异代码和验证记录。
- 表达：分别说明开源原有功能、本人验证、AI 辅助和个人改进。
